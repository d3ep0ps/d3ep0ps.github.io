# Досить Клікати: Шлях до Infrastructure as Code

*Від Vagrant на вашому ноутбуці до Terraform у хмарі — як будувати системи, що виживають.*

Ми обрали нашу Операційну Систему (Linux або FreeBSD). Ми навчилися редагувати файли за допомогою `vi`. Ми зрозуміли, як Фаєрвол та Хмарні Фаєрволи фільтрують трафік до того, як він досягне нас.

Але на нас все ще чекає небезпечна пастка.

Це пастка "Pet Server" (Сервер-Улюбленець).

Ви знаєте цей сервер. Це той, який ви вручну встановили, вручну пропатчили і вручну налаштовували протягом трьох років. Він працює ідеально, але ви боїтеся його торкатися. Якщо він помре, ви не знаєте, чи зможете коли-небудь побудувати його знову.

Ця стаття про втечу від цього страху.

Вона про **Infrastructure as Code (IaC)** — дисципліну визначення ваших систем у текстових файлах, а не в ручних кліках.

Ми почнемо локально, у безпеці вашої домашньої лабораторії, і прокладемо шлях до глобального хмарного масштабу.

## Рівень 1: Чистий Аркуш (VirtualBox & Vagrant)

Перш ніж автоматизувати хмару, ми повинні автоматизувати наш ноутбук.

Якщо ви хочете протестувати нове правило фаєрволу або міграцію бази даних, вам потрібне безпечне середовище. Ви могли б завантажити ISO, відкрити VirtualBox, натиснути "New VM", встановити RAM, змонтувати диск, проклацати інсталятор…

Але це повільно. І оскільки це повільно, ви не будете робити це часто.

Зустрічайте **Vagrant**.

Vagrant — це інструмент, який створює відтворювані середовища розробки. Він обгортає гіпервізори, такі як VirtualBox (або VMware/Libvirt), і дозволяє вам визначити машину в одному файлі: `Vagrantfile`.

Ось різниця між "клацанням" та "кодингом":

```ruby
# Vagrantfile
Vagrant.configure("2") do |config|
  config.vm.box = "ubuntu/jammy64"
  config.vm.network "private_network", ip: "192.168.56.10"
  config.vm.provider "virtualbox" do |vb|
    vb.memory = "2048"
    vb.cpus = 2
  end
end
```

З цим файлом у папці ви запускаєте одну команду:
`vagrant up`

Vagrant завантажує образ, будує VM, налаштовує мережу і вручає вам ключі. Коли ви зламаєте її (а ви повинні її зламати), ви запускаєте:
`vagrant destroy`

А потім `vagrant up` знову. Через 60 секунд у вас є свіжий, ідеальний клон.

**Урок:** Інфраструктура має бути одноразовою.

## Рівень 2: Золотий Образ (Packer)

Vagrant чудовий, але він починається з "базового" образу ОС. Кожного разу, коли ви завантажуєтесь, вам потрібно запускати `apt-get update`, встановлювати ваші інструменти та налаштовувати користувачів. Це займає час.

Що, якби ви могли спекти свою власну "стартову точку"?

Зустрічайте **Packer**.

Packer автоматизує створення образів машин. Він піднімає машину, запускає ваші скрипти інсталяції і зберігає результат як "Золотий Образ" (файл `.box` для Vagrant або AMI для AWS).

Замість того, щоб налаштовувати сервер після його завантаження, ви налаштовуєте *образ* до того, як він існує.

**Урок:** Не витрачайте час на встановлення тих самих пакетів тисячу разів. Спечіть один раз, розгортайте всюди.

## Рівень 3: Менеджер (Ansible)

Тепер у вас є працюючий сервер. Як ви налаштовуєте програмне забезпечення всередині нього?

У вас може виникнути спокуса написати shell-скрипт:
`apt-get install nginx`
`echo "server { ... }" > /etc/nginx/nginx.conf`

Але shell-скрипти крихкі. Якщо ви запустите цей скрипт двічі, чи зламає він конфіг-файл? Якщо `nginx` вже встановлено, чи впаде він з помилкою?

Саме тут вступає в гру **Configuration Management** (Управління Конфігурацією).
Зустрічайте **Ansible**.

Ansible не просто запускає команди; він забезпечує *стан*. Він **ідемпотентний** — модне слово, що означає "запуск цього кілька разів дає той самий результат".

Замість того, щоб казати "Встанови Nginx" (імперативно), ви кажете "Забезпеч, щоб Nginx був присутній" (декларативно).

```yaml
# playbook.yml
- name: Configure Web Server
  hosts: all
  tasks:
    - name: Ensure Nginx is installed
      apt:
        name: nginx
        state: present

    - name: Ensure config file matches our standard
      copy:
        src: ./nginx.conf
        dest: /etc/nginx/sites-available/default
      notify: Restart Nginx
```

Ви можете запустити це проти однієї VirtualBox VM або 500 хмарних серверів. Результат — математично послідовна інфраструктура.

**Урок:** Визначайте *бажаний стан*, а не кроки для його досягнення.

## Рівень 4: Архітектор (Terraform)

Ми опанували локальну лабораторію. У нас є наші образи. У нас є наша конфігурація.
Тепер ми рухаємося в Хмару.

В AWS або Google Cloud вам потрібна не просто VM. Вам потрібні VPC, Підмережа, Правила Фаєрволу, Балансувальник Навантаження та Сервісний Акаунт.

Клацання через консоль AWS чи GCP для побудови цього — це кошмар. Це невідтворювано, не піддається аудиту і схильне до помилок.

Зустрічайте **Terraform**.

Terraform — це індустріальний стандарт для **Infrastructure Provisioning** (Розгортання Інфраструктури). Він говорить з API хмар, щоб побудувати "скелет" вашої інфраструктури.

Поки Ansible керує тим, *що відбувається всередині* сервера, Terraform керує *самим сервером* (і мережею навколо нього).

```hcl
# main.tf
resource "google_compute_network" "vpc_network" {
  name = "d3ep0ps-vpc"
}

resource "google_compute_instance" "vm_instance" {
  name         = "web-server"
  machine_type = "e2-micro"
  
  boot_disk {
    initialize_params {
      image = "debian-cloud/debian-11"
    }
  }
}
```

Коли ви запускаєте `terraform apply`, він дивиться на ваш код, дивиться на реальну хмару, вираховує різницю і приводить все у відповідність.

**Урок:** Весь ваш дата-центр має бути визначений у git-репозиторії.

### Уніфікована Філософія

Чому це важливо? Навіщо вчити чотири інструменти замість простого натискання кнопок?

Тому що **Кодифікована Інфраструктура** приносить спокій.

  * **Вона документує сама себе.** Вам не потрібна сторінка у Wiki, що пояснює, як налаштований сервер. Код *і є* поясненням.
  * **Вона уможливлює відновлення.** Якщо регіон падає або ноутбук вкрадено, ви не панікуєте. Ви стягуєте код, запускаєте команду і чекаєте.
  * **Вона дозволяє експериментувати.** Ви можете підняти копію продакшену, протестувати божевільну ідею і знищити її за копійки.

**Крок 1: Отримайте Інструменти**
Перш ніж ви зможете щось автоматизувати, вам потрібен двигун. Завантажте та встановіть ці інструменти для вашої ОС:

  * **VirtualBox** (Гіпервізор): [virtualbox.org](https://www.virtualbox.org/)
  * **Vagrant** (Менеджер VM): [vagrantup.com](https://www.vagrantup.com/)
  * **Packer** (Будівельник Образів): [packer.io](https://www.packer.io/)
  * **Terraform** (Хмарний Будівельник): [terraform.io](https://www.terraform.io/)

**Крок 2: Клонуйте Лабу**
Стягніть креслення:

```bash
git clone https://github.com/d3ep0ps/iac-lab
cd iac-lab
```

**Крок 3: Запустіть Рівні**

  * **Рівень 1 (Vagrant):** Перейдіть у `level1-vagrant` і запустіть `vagrant up`. Тепер у вас є сервер.
  * **Рівень 2 (Packer):** Перейдіть у `level2-packer` і запустіть `packer init .` потім `packer build .`. Дивіться, як він пече кастомний образ автоматично.
  * **Рівень 3 (Ansible):** Перейдіть у `level3-ansible` і запустіть `vagrant up`. Дивіться, як він налаштовує Nginx, а ви навіть пальцем не поворухнули.
  * **Рівень 4 (Terraform):** Перейдіть у `level4-terraform`, щоб побачити хмарне креслення.
